## 下次升级

1. 查看上游最新稳定发布，固定发布标签和对应提交；先备份工作区改动及本机配置。
2. 从当前 Fork 建立 `codex/` 前缀的独立升级分支。先读补丁登记表，逐项比较登记文件。
3. 合并发布标签，保留上游执行引擎和目录布局，在供应商协议边界维护阿里云补丁。
4. 先处理导入与构建问题，再核对模型、会话、工具执行和流结束行为。
5. 完成全部 Python 测试、前端检查与构建、文档和技能校验；运行 Easel 环境及连通性检查，实际启动 Web。
6. 核对六个通道、配置摘要、账号和画像状态。变更了供应商协议的通道需重新实测；旧实测记录仅代表匹配配置的历史结果。
7. 更新补丁登记表和必要的 ADR；验收通过后更新自己的 Fork。
